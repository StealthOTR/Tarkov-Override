# Tarkov Override 1.0.4

**Author: StealthOTR**

A configurable sandbox and practice toolkit for solo SPT 4.1.6, with a compact in-game menu, contextual tooltips and editable JSON hotkeys.

## Requirements

- Exactly SPT 4.1.6 with its bundled BepInEx installation.
- Solo play. The plugin disables itself when Fika is detected.
- BepInEx ConfigurationManager is optional; the compact menu has its own controls.

## Install or update

1. Close Escape from Tarkov.
2. Extract this package's BepInEx folder into your SPT installation folder.
3. Replace BepInEx/plugins/SPTPracticeMenu/SPTPracticeMenu.dll if prompted. Keep only one copy of the plugin.
4. Start SPT and open Tarkov Override with Insert, or your existing OpenSettings binding.

The internal DLL folder/name, plugin GUID and configuration paths are intentionally retained from SPT Field Toolkit. This allows existing installations to update in place without a second plugin or lost settings. The displayed mod name, header, author credit, version metadata and release branding are Tarkov Override.

No installed configuration is included in the archive. Existing settings and hotkeys remain in place. On a fresh installation, defaults are generated by the plugin. examples/config.example.json is reference-only: do not overwrite your existing bindings with it unless you want those defaults.

## Rage ADS weapon stability in 1.0.4

Rage Aim now includes No ADS movement sway under Weapon Stability, enabled by default. With the Rage master enabled and your held firearm actually aiming down sights, it suppresses local movement/turn sway and walking bob, including overweight walking bob. No target lock is required. It does not apply to bots, Legit Aim or hip-fire. Values are filtered only while processing your own animation effectors, so no weapon templates or stored animation settings are modified. Recoil remains separate under RCS; breathing/injury effects and unrelated animations are not removed by this movement-sway option.

## Rage tracking changes in 1.0.3

Strict Head Targeting now forces Head even if another Target bone is saved, and disables the body-point/fallback controls while active. Head tracking uses one cached model-skeleton head transform per enemy, with a fixed original-head-bone fallback if the model rig has no matching head. It no longer alternates with collider centres. Rage Instant lock computes rotation from the native player LookDirection instead of the rendered camera's delayed/animated direction.

Rage Aim also has independent Movement prediction and Bullet drop compensation switches under Movement & Bullet Drop. Both default off so head lock can be checked without compensation first. Prediction strength and a maximum flight-time bound are configurable. Estimates use current ammo/weapon speed, target velocity and gravity; air drag and zeroing are not fully modelled. No firing block or trigger control was added. The selected-target marker remains on the current anatomical point even when compensation aims ahead/above it.

## Live head coordinates in 1.0.2

Head targeting now anchors to the original animated head transform, not physics bounds or imitation/accumulated bone positions. A collider centre is used only if it belongs beneath that live head in the hierarchy and is within 22 cm of it. Missing/invalid live head data is rejected instead of guessing a standing height. Tracking status identifies the live source. Overlay projection uses viewport coordinates to remain independent of render-texture resolution. Check actual marker placement and ADS aiming in a raid; these changes are not a claim of verified live shot accuracy.

## Aim correction in 1.0.1

Rage Aim now includes Strict head targeting, enabled by default. When Head is selected, a failed head visibility/range/FOV check skips that enemy instead of falling back to chest or pelvis. Disable Strict head targeting if you intentionally want the existing Aim point fallback behaviour. Nearest-to-crosshair and explicit chest/pelvis choices retain their normal behaviour. Head targeting prefers the actual enabled head hitbox centre; tracking status names the chosen aim point and any fallback. Live shot placement still needs an in-raid check.

## Controls and configuration

- Insert: compact menu; Escape closes it.
- F6/F7/F8: enemy ESP, loot ESP and active aim mode.
- F9: reload JSON bindings. F10: Panic.
- F12: optional BepInEx ConfigurationManager backup.

These are defaults. Hotkeys live in BepInEx/config/SPTFieldToolkit/config.json. Edit that file or type bindings in Keys and save. Key capture is not used. Missing newer properties retain their defaults. Gameplay settings use the existing local.spt.practicemenu.cfg and save when the menu closes.

The menu blocks character input while open but does not pause the raid. New Player/Misc practice toggles reset between raids and on Panic. One-shot repairs, spawned loot and requested airdrops are normal world/inventory changes and are not undone by Panic.

## Features

- Enemy and body ESP, type filters/colours, health, skeletons and visibility controls.
- Loot categories/presets, quest and wishlist highlighting, clustering and clutter controls.
- Separate Legit Aim and Rage Aim profiles with configurable target selection, exclusions, switching and RCS.
- Player practice controls, health restoration, Demigod, stamina, malfunction prevention, gear repair, medical supplies, weight and fire-rate overrides.
- Night/thermal vision, No Flash, No Visor, no-clip and adjustable interaction range.
- Door unlocking, extraction controls and a native airdrop request button on supported maps.
- Searchable in-raid item spawning and independent nearby-enemy alerts.

Author credit stays in the compact window header and is visible on every tab. Vampire Mode remains planned. Grenade trajectory preview has been removed.

## Remove

Close the game and remove BepInEx/plugins/SPTPracticeMenu/SPTPracticeMenu.dll. Config files can be kept for reinstalling or removed separately. Removing the mod does not reverse inventory items or repairs already saved during play.

## Source

A separate source archive contains the C# files and Build.ps1. Run Build.ps1 -SptPath 'your SPT folder' to compile against your own installed game/BepInEx references. It writes beside the source and does not install the DLL. No game or third-party DLLs are redistributed in the source archive.
